# 의도적으로 문서화하지 않은 릴리스

`release.sh` 는 직전 태그 이후 UI 를 건드린 `feat:` 커밋이 있는데 `assets/` 에 **새로 추가된**
파일이 없으면 배포를 중단한다. 새 기능이 그림 한 장 없이 나가는 걸 막는 게이트다(2.5.0 에서
플로팅 펫이 정확히 그렇게 나갔다).

그 게이트의 전제는 **"새 기능은 사용자에게 보여줘야 한다"** 인데, 여기에 안 맞는 부류가 하나 있다:
**찾는 재미가 곧 내용인 기능.** 스크린샷을 만들어 README 와 랜딩에 올리는 순간 그 기능은 목적을
잃는다. 게이트를 통과하려고 이미지를 만드는 것이 기능을 망치는, 유일한 경우다.

그래서 이 파일이 있다. 버전을 적으면 그 버전에 한해 게이트가 통과한다.

**규칙 셋:**

- **버전 단위로만 연다.** `## 1.3.2` 처럼 정확히 그 버전을 적어야 하고, 다음 릴리스는 다시 막힌다.
  한 번 적어 두면 계속 열리는 우회구가 아니다.
- **이유를 같이 적는다.** 나중에 읽는 사람이 "그림이 귀찮아서"와 "그림을 만들면 안 되는 것"을
  구분할 수 있어야 한다.
- **커밋 타입은 손대지 않는다.** 게이트를 피하려고 `feat:` 을 `chore:` 로 고쳐 다는 건 히스토리를
  거짓으로 만드는 일이다. 기능이면 `feat:` 이고, 예외는 여기에 남긴다.

숨기는 것은 릴리스 노트와 문서까지다. **커밋 메시지와 코드는 그대로 둔다** — 저장소를 읽는 사람에게
숨길 방법도 없고, 숨기면 코드를 읽기 어렵게 만드는 대가만 치른다.

## 1.3.2

부화 슬롯 연출 수정과 함께, 사용자가 스스로 마주치도록 둔 것이 하나 들어간다. 어떤 조건에서
무엇이 일어나는지는 커밋 히스토리에 다 적혀 있다 — 다만 릴리스 노트·README·랜딩에는 넣지 않는다.
직접 마주쳤을 때의 놀라움이 그 기능이 가진 전부라서, 미리 알려 주면 남는 게 없다.
