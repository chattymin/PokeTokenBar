# PokeDexBar — 설계 문서 (2026-08-03)

## 목적

Claude Code 등 AI CLI의 토큰 사용량을 포켓몬 수집으로 바꾸는 macOS 메뉴바 앱.
[PokeTokenBar](https://github.com/chattymin/PokeTokenBar)(MIT, chattymin)를 포크해
두 가지를 바꾼다.

1. **전 세대 개방** — 스프라이트 소스를 PokeAPI Gen-V(649종 상한)에서
   Pokémon Showdown으로 교체해 9세대까지 1,025종을 다룬다.
2. **안티앨리어싱** — 저해상도 스프라이트를 크게 띄워도 뭉개지지 않게 EPX 업스케일링을 넣는다.

이어서 게임 경제를 "졸업해야 다음 알"에서 "토큰으로 알을 뽑고 시간이 지나면 부화"로
교체한다(2단계).

- 대상: macOS 14+, Swift 6, SwiftPM
- 저장소: `chattymin/PokeTokenBar`의 GitHub 정식 포크 → `PokeDexBar`로 리네임
- 업스트림 연결 유지 — 원본 개선을 병합해 오고, 전 세대 스프라이트·안티앨리어싱은
  업스트림에 PR로 되돌려줄 수 있다

## 1단계 — 포크 · 리브랜딩 · 전 세대 · 안티앨리어싱

동작하는 앱을 먼저 확보하는 단계. 게임 로직(부화·진화·도감·상점)은 업스트림 그대로 둔다.

### 리브랜딩

`PokeTokenBar` → `PokeDexBar`. 손볼 지점은 다음이 전부다.

| 대상 | 현재 | 변경 |
|---|---|---|
| 번들 ID | `io.github.chattymin.poketokenbar` | `io.github.leedg0831.pokedexbar` |
| 타깃·디렉토리 | `Sources/PokeTokenBar` | `Sources/PokeDexBar` |
| LoginItem | `…poketokenbar.login(.plist)` | `…pokedexbar.login(.plist)` |
| UpdateChecker | `repo = "chattymin/PokeTokenBar"` | 우리 저장소 |
| AppLog 큐 | `poketokenbar.log` | `pokedexbar.log` |
| ProcessRunner 임시파일 | `poketokenbar-*.jsonl` | `pokedexbar-*.jsonl` |
| 데이터 폴더 | `~/Library/Application Support/PokeTokenBar` | `…/PokeDexBar` |

데이터 폴더가 분리되므로 **홈브루로 설치된 PokeTokenBar와 동시에 실행된다**(메뉴바 아이콘 2개).
기존 PokeTokenBar 상태는 건드리지 않는다 — 이전(migration)도 하지 않는다.

MIT 라이선스와 chattymin 저작권 표기는 그대로 두고, README에 포크임을 명시한다.

### 스프라이트 계층 교체

업스트림이 1~5세대에 묶인 이유는 **Gen-V 애니메이션 스프라이트가 649번까지만 있어서**다
(`PokeAPIClient.swift`의 `id ≤ 649` 필터에 그렇게 적혀 있다). 게임 데이터(진화 체인·포획률·
다국어 이름)는 PokeAPI가 이미 전 세대를 준다. 따라서 스프라이트 URL만 갈아끼우면 된다.

- **소스**: `play.pokemonshowdown.com/sprites/`
  - 애니메이션: `ani/<slug>.gif`, 이로치 `ani-shiny/<slug>.gif`
  - 정적: `gen5/<slug>.png`, 이로치 `gen5-shiny/<slug>.png`
- **폴백 체인**: 애니메이션 → 정적 → 알 이모지. 업스트림에 이미 있는 구조를 그대로 쓴다.
  9세대 일부(오거폰·테라파고스·아이언크라운 등)는 애니메이션이 없어 정적으로 떨어진다
  (표본 20종 중 4종). 실측으로 확인했다.
- **종 ID → 슬러그 매핑**: 업스트림은 숫자 종 ID로 동작하고 Showdown은 이름 슬러그를 쓴다
  (`bulbasaur`, `ho-oh`). `num → slug` 매핑 파일을 생성 스크립트로 1회 만들어 앱에 번들한다.
  런타임 네트워크 0, 결정적. (대안이던 "이름을 규칙으로 변환"은 `Nidoran♀`·`Mr. Mime`·
  `Farfetch'd`·`Type: Null` 같은 예외가 많아 깨지기 쉽고, "런타임에 pokedex.json 다운로드"는
  시작을 네트워크에 묶는다.)
- **캐시**: 기존 디스크 캐시 구조를 유지하되 키를 슬러그 기반으로 바꾼다. 애니메이션이 없는
  종은 실패를 메모리에 기억해 매번 재시도하지 않는다.

### 세대 제한 해제

`PokeAPIClient`의 `id ≤ 649` 필터를 제거하면 부화 풀이 1,025종이 된다. 희귀도(포획률 기반)·
진화 체인·이름은 PokeAPI가 전 세대를 제공하므로 **밸런스 로직은 손대지 않는다.**
`base-index.json` 캐시는 첫 실행에 새 범위로 다시 채워진다.

### 안티앨리어싱

PokeRunBar에서 만든 EPX 업스케일러와 정수배 스케일링을 이식한다.

- `PixelUpscaler.swift` — EPX(Eric's Pixel Expansion) 2배 확대
- `PixelScale.swift` — 표시 크기에 맞는 정수배 계산
- 설정에 토글(기본 켬). 끄면 기존 최근접 이웃 렌더링.
- 적용 지점: 메뉴바 아이콘, 팝오버 컴패니언, 플로팅 펫, 도감 썸네일

### 검증

- **1차 게이트**: 업스트림 테스트 421개가 리네임 후에도 통과
- 추가 테스트: 슬러그 매핑(예외 종 포함), 스프라이트 URL 구성, 폴백 체인(애니메이션 없는 종),
  EPX 업스케일러
- 렌더 덤프로 9세대 스프라이트가 실제로 그려지는지 눈으로 확인

## 2단계 — 경제 교체 (설계만, 구현은 다음 사이클)

"졸업해야 다음 알"을 버리고 **토큰 → 재화 → 알 뽑기 → 시간 부화 → 경험치 진화**로 바꾼다.

### 재화

사용한 토큰이 곧 재화다: `잔액 = 누적 사용 토큰 − 지출`. 업스트림의 지갑 구조
(`usedSinceInstall − spentTokens`)를 그대로 재사용한다. 표기는 압축형(`265.8M`).

### 알과 등급 — 뽑기로만 얻는다

**등급을 지정해 살 수 없다.** 상점에서 파는 것은 "알 뽑기" 한 종류이고, 나오는 등급은 확률로
정해진다. 레전더리는 돈으로 사는 것이 아니라 운으로 얻는다.

포획률로 4등급을 나눈다. 업스트림의 4단 희귀도를 다시 매핑하는 것이라 로직 변경이 작다.

| 등급 | 기준 | 뽑기 확률(초안) | 부화 시간(초안) |
|---|---|---|---|
| 커먼 | 포획률 ≥ 121 | 70% | 30분 |
| 레어 | 포획률 46~120 | 22% | 2시간 |
| 에픽 | 포획률 ≤ 45 (전설 제외) | 7% | 6시간 |
| 레전더리 | 전설·환상 | 1% | 24시간 |

- 뽑기 가격 초안 **150M/회**. 확률은 상점에 그대로 표기한다(숨기지 않는다).
- **슬롯이 비어 있어야 뽑을 수 있다** — 미부화 알 보관함을 따로 두지 않는다. 뽑는 즉시 그
  슬롯에서 부화가 시작되므로, 슬롯이 곧 "지금 몇 개를 굴리고 있나"다.
- 종은 **뽑는 시점에 몰래 추첨**해 스프라이트를 미리 받아두고, 부화 때 공개한다.
- 천장(일정 횟수 안에 에픽 이상 보장)은 실제로 굴려 보고 필요하면 붙인다 — 처음엔 없이 간다.

### 부화

토큰이 아니라 **실시간 경과**로 깬다. 알은 `구매 시각 + 등급별 소요시간`을 들고 있고,
앱이 꺼져 있는 동안에도 시간은 흐른다(실행 시 경과분을 정산). 부화 알림을 보낸다.

### 슬롯

기본 3개 동시 부화. 상점에서 확장하며 가격은 체증한다(4번째 500M, 5번째 1.5B, 6번째 4B,
상한 6). 슬롯이 꽉 차면 뽑기를 돌릴 수 없다 — 슬롯 확장이 곧 뽑기 회전율이라 재화의 주요
사용처가 된다.

### 경험치와 진화

- **파트너 자동 적립**: 메뉴바에 데리고 다니는 파트너는 토큰을 쓸 때마다 그만큼 경험치를 얻는다.
  (재화와 경험치는 같은 활동을 먹는 별개 미터다 — 업스트림도 성장 미터와 지갑이 그랬다.)
- **경험치 사탕**: 지정한 개체에 즉시 경험치를 준다(부스터).
- **진화**: 임계 도달 시 "진화 가능" 배지가 뜨고 **사용자가 눌러야** 진화한다. 미룰 수 있고,
  분기 진화는 어느 쪽으로 갈지 고른다. 임계는 업스트림의 `phaseThreshold(희귀도·형태수·단계)`
  형태를 재사용하고 수치는 실측 후 조정한다.

### 상점 품목

| 품목 | 효과 | 가격(초안) |
|---|---|---|
| 알 뽑기 | 등급이 확률로 정해진 알 1개 (빈 슬롯 필요) | 150M/회 |
| 부화 슬롯 확장 | 동시 부화 +1 (상한 6) | 500M ~ 4B |
| 이로치 부적 | 영구 — 이후 부화 이로치 확률 1/64 → 1/48 | 3B |
| 경험치 사탕 | 지정 개체에 경험치 +100M | 500M |
| 반짝이는 사탕 | 지정 개체를 이로치로 바꾼다 | 2B |

### 수집 — 중복 허용

졸업 개념이 없다. 부화한 개체는 계속 보유하며, **같은 종이 여러 마리 나올 수 있다.**
수집은 종 집합이 아니라 **개체 목록**이다 — 개체마다 종·이로치·성격·경험치·진화 단계가 따로 간다.

- 업스트림의 "이미 모은 종은 덜 나오게" 다양성 로직(`collectedFinals` 기반)은 제거한다.
- 중복은 쓸모가 있다: 분기 진화를 서로 다르게 태우거나, 반짝이는 사탕을 어디에 쓸지 고른다.
- 도감은 두 숫자로 보여준다 — 고유 종 N / 보유 개체 M.
- 파트너는 보유 개체 중 하나를 지정한다.

### 1단계에 주는 제약

2단계에서 `CompanionState`/`CompanionStore`(현재 경제가 박혀 있는 곳)를 통째로 교체한다.
따라서 **1단계에서는 그 영역을 리팩터링하지 않는다** — 스프라이트 계층과 리브랜딩만 건드린다.
버릴 코드에 공들이지 않기 위해서다.

## 비범위

- 세션 모니터링(진행 중인 Claude 세션 표시) — PokeRunBar에 있지만 가져오지 않는다
- 폼·리전폼·메가진화 — 게임이 종 단위 진화라 해당 없음
- 업스트림의 릴리스 자동화(홈브루 cask·랜딩 페이지) — 처음엔 끈다
- 기존 PokeTokenBar 상태 이전 — 두 앱은 독립적으로 공존한다
