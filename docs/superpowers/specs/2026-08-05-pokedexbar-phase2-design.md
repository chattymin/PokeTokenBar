# PokeDexBar 2단계 — 경제 교체 설계 (2026-08-05)

1단계(포크·전 세대 스프라이트·안티앨리어싱)는 `main` 에 병합됐다. 이 문서는 게임을 통째로
바꾸는 2단계 설계다. 1단계가 손대지 않고 남겨둔 `CompanionState`/`CompanionStore` 가 여기서
교체된다.

## 무엇이 바뀌나

지금(업스트림 계승): 알 하나로 시작 → 토큰 5M 쓰면 부화 → 토큰이 성장 미터를 채워 자동 진화 →
졸업하면 도감에 남고 새 알. 한 번에 한 마리, 중복 없음.

바꾼 뒤:

1. **첫 실행에 스타터를 고른다.** 전 세대 1단계 스타터 27마리 중 하나. 알로 시작하지 않는다.
2. **토큰을 쓰면 재화가 쌓인다.** 그 재화로 상점에서 **알 뽑기**를 돌린다 — 등급을 지정해 살 수 없다.
3. **알은 시간이 지나면 깨진다.** 토큰이 아니라 실시간. 등급마다 걸리는 시간이 다르고, 여러 개를
   동시에 부화시킬 수 있다.
4. **경험치로 진화한다.** 파트너는 토큰을 쓸 때마다 경험치를 얻고, 경험치 사탕으로 부스트한다.
   임계에 닿으면 **사용자가 눌러서** 진화한다.
5. **졸업이 없다.** 부화한 개체는 계속 보유하고, **같은 종이 여러 마리 나올 수 있다.**
6. **도감과 박스가 나뉜다.** 도감은 종 수집 진행판, 박스는 내 개체 목록.

## 상태 모델

`CompanionState` 를 대체하는 새 모델. 개체(individual)와 종(species)을 구분하는 것이 핵심이다 —
중복이 생기는 순간 "무엇을 가졌나"와 "무엇을 모았나"는 다른 질문이 된다.

```
PlayerState
  starterChosen: Bool          // 첫 실행 스타터 선택을 마쳤나
  earnedTokens: Int            // 설치 이후 누적 사용 토큰(재화의 원천)
  spentTokens: Int             // 상점 지출 누적
  partnerID: UUID?             // 박스의 어느 개체를 데리고 다니나
  box: [Individual]            // 보유 개체 — 중복 허용
  dex: Set<Int>                // 한 번이라도 보유한 종 번호
  slots: Int                   // 동시 부화 가능 수 (3…6)
  eggs: [Egg]                  // 부화 중인 알 (count ≤ slots)
  inventory: [String: Int]     // 아이템 종류 → 개수
  ownsShinyCharm: Bool

Individual
  id: UUID
  baseID: Int                  // 처음 만난 형태(스타터/부화체)
  speciesID: Int               // 지금 형태
  pathIDs: [Int]               // 실제로 지나온 진화 경로
  shiny: Bool
  nature: PokemonNature
  exp: Int                     // 현재 단계에서 쌓은 경험치
  obtainedAt: Date
  grade: Grade                 // 커먼/레어/에픽/레전더리 (포획률 기반, 표시·임계용)

Egg
  id: UUID
  grade: Grade
  speciesID: Int               // 뽑는 순간 몰래 정해둔다(스프라이트 예열용). 부화 때 공개
  shiny: Bool                  // 뽑는 순간 결정
  startedAt: Date
  hatchesAt: Date              // startedAt + 등급별 소요시간
```

지갑 잔액 = `earnedTokens − spentTokens`. 업스트림 지갑 구조를 그대로 이어받는다.

## 시작 — 스타터 선택

첫 실행(`starterChosen == false`)에 팝오버가 스타터 선택 화면을 띄운다. 27마리 그리드,
세대별로 묶어 보여준다.

| 세대 | 스타터 (종 번호) |
|---|---|
| 1 | 1 · 4 · 7 | 2 | 152 · 155 · 158 | 3 | 252 · 255 · 258 |
| 4 | 387 · 390 · 393 | 5 | 495 · 498 · 501 | 6 | 650 · 653 · 656 |
| 7 | 722 · 725 · 728 | 8 | 810 · 813 · 816 | 9 | 906 · 909 · 912 |

- 고르면 그 종의 개체가 만들어져 박스에 들어가고 **파트너로 지정**된다. 도감에도 등록된다.
- 스타터는 **이로치가 아니다.** 이로치는 부화와 반짝이는 사탕으로만 만난다 — 첫 개체는 복구할 수
  없으니 운에 맡기지 않는다.
- 성격은 무작위. 등급은 그 종의 포획률로 계산한다(스타터는 대개 레어).
- 선택 전에는 다른 탭을 쓸 수 없다. 고르는 것이 이 앱의 시작이다.

## 재화

토큰을 쓰면 그만큼 재화가 쌓인다. 표기는 압축형(`265.8M`). 재화와 경험치는 같은 활동을 먹는
별개 미터다 — 파트너가 경험치를 얻는다고 지갑이 줄지 않는다.

## 알 — 뽑기로만 얻는다

등급을 지정해 살 수 없다. 상점에서 파는 것은 "알 뽑기" 한 종류이고 등급은 확률로 정해진다.
레전더리는 돈이 아니라 운으로 얻는다. 확률은 상점에 그대로 표기한다.

| 등급 | 종 기준(포획률) | 뽑기 확률 | 부화 시간 |
|---|---|---|---|
| 커먼 | ≥ 121 | 70% | 30분 |
| 레어 | 46 ~ 120 | 22% | 2시간 |
| 에픽 | ≤ 45 (전설 제외) | 7% | 6시간 |
| 레전더리 | 전설·환상 | 1% | 24시간 |

- 뽑기 가격 **150M/회**.
- **빈 슬롯이 있어야 뽑을 수 있다.** 미부화 알 보관함은 두지 않는다 — 뽑는 즉시 그 슬롯에서
  부화가 시작되므로, 슬롯이 곧 "지금 몇 개를 굴리고 있나"다.
- 종은 뽑는 순간 등급 안에서 포획률 가중으로 정하고 스프라이트를 미리 받아둔다. 부화 때 공개.
- 이로치 판정도 뽑는 순간. 기본 1/64, 이로치 부적 보유 시 1/48.
- 천장(일정 횟수 안에 에픽 이상 보장)은 실제로 굴려 보고 필요하면 붙인다 — 처음엔 없이 간다.

## 부화 — 시간

`hatchesAt` 에 도달하면 깨진다. 앱이 꺼져 있는 동안에도 시간은 흐르고, 다음 실행에서 경과분을
정산해 한꺼번에 부화시킨다. 부화하면 알림을 보내고 개체가 박스에 들어간다.

## 슬롯

기본 3개. 상점에서 확장하며 가격은 체증한다 — 4번째 500M, 5번째 1.5B, 6번째 4B(상한 6).
슬롯이 꽉 차면 뽑기를 돌릴 수 없으므로 슬롯 확장이 곧 뽑기 회전율이고, 재화의 주요 사용처가 된다.

## 경험치와 진화

- **파트너 자동 적립**: 파트너는 토큰 사용량만큼 경험치를 얻는다. 박스의 다른 개체는 얻지 않는다.
- **경험치 사탕**: 지정한 개체에 즉시 경험치를 준다.
- **진화**: 임계에 도달하면 "진화 가능" 배지가 뜨고 **사용자가 눌러야** 진화한다. 미룰 수 있고,
  분기 진화(이브이류)는 어느 쪽으로 갈지 고른다. 진화하면 `speciesID`·`pathIDs` 가 갱신되고
  새 종이 도감에 등록되며, `exp` 는 0으로 돌아가고 초과분은 이월한다.
- **임계(초안)**: 등급과 현재 단계로 정한다. 진화가 없는 종은 최종형으로 표시만 한다.

| 등급 | 1→2단계 | 2→3단계 |
|---|---|---|
| 커먼 | 50M | 150M |
| 레어 | 100M | 300M |
| 에픽 | 200M | 600M |
| 레전더리 | 400M | 1.2B |

## 상점

| 품목 | 효과 | 가격 |
|---|---|---|
| 알 뽑기 | 등급이 확률로 정해진 알 1개 (빈 슬롯 필요) | 150M/회 |
| 부화 슬롯 확장 | 동시 부화 +1 (상한 6) | 500M / 1.5B / 4B |
| 이로치 부적 | 영구 — 이후 부화 이로치 확률 1/64 → 1/48 | 3B |
| 경험치 사탕 | 지정 개체에 경험치 +100M | 500M |
| 반짝이는 사탕 | 지정 개체를 이로치로 바꾼다 | 2B |

## 도감 — 전국도감식

희귀도로 나누지 않는다. **1번부터 1025번까지 번호순 그리드**다.

- 잡은 종은 컬러 스프라이트, 못 잡은 종은 **실루엣 + 번호**.
- 등록 기준은 **한 번이라도 보유한 종**. 방생이 없으니 지금 보유 + 진화로 지나온 형태가 전부 포함된다
  (이상해씨를 이상해풀로 진화시키면 2번도 등록).
- 상단에 진행률(`142 / 1025`).
- **보이는 칸만 스프라이트를 받는다.** 1025칸을 한 번에 그리면 팝오버가 버벅인다 — 지연 그리드로
  가시 영역만 로드한다.
- 읽기 전용이다. 포켓몬을 만지는 일은 전부 박스에서 한다.

## 박스 — 내 포켓몬

보유 **개체** 목록. 같은 종이 여러 마리면 각자 한 칸을 차지한다.

- 개체마다 종·이로치·성격·경험치 진행도·"진화 가능" 배지·파트너 배지.
- 여기서 **파트너 지정 · 경험치 사탕 · 반짝이는 사탕 · 진화 실행**을 한다.
- 최근 획득 순 정렬. 용량 제한 없음.

## 탭 구성

**홈 / 박스 / 도감 / 상점**. 홈은 파트너 카드(경험치 진행도·진화 배지) + 부화 중인 알 슬롯 +
오늘 토큰·재화 잔액. 스타터를 고르기 전에는 홈 자리에 선택 화면만 뜬다.

## 버리는 것

업스트림에서 이어받았지만 이 설계와 맞지 않아 제거하는 것들:

- 알 인큐베이션(`eggUsage`)과 5M 토큰 부화 임계
- 졸업(`graduate`)과 그에 따른 도감 등록 — 개체는 계속 보유한다
- `collectedFinals` 기반 "이미 모은 종은 덜 나오게" 다양성 로직 — 중복이 정상이다
- 자동 진화(`applyUsage` 의 임계 도달 즉시 진화) — 사용자가 누른다
- 메타몽 위장 리빌 — 뽑기·시간 부화와 엮이지 않는다
- 이상한 사탕/민트/이로치 부적의 기존 가격 체계 — 새 상점 표로 대체

## 단계 분할

한 번에 다 만들지 않는다. 각 단계가 그 자체로 동작하는 앱이어야 한다.

**2a — 기반**: 새 상태 모델, 스타터 선택, 재화 적립, 파트너 경험치·수동 진화, 박스 UI, 도감 UI.
알·뽑기·상점은 아직 없다. 이 단계가 끝나면 "스타터를 골라 키우고 진화시키고 도감이 차는" 앱이 된다.

**2b — 경제**: 상점, 알 뽑기, 슬롯, 시간 부화, 부화 알림, 아이템 4종. 이 단계가 끝나면 설계 전체가
동작한다.

## 검증

- 순수 로직(등급 판정·뽑기 확률·부화 시각·경험치 임계·도감 등록)은 전부 단위 테스트로 잠근다.
- 시간 부화는 주입한 시계로 테스트한다 — 실제 대기 없이 경과를 시뮬레이션한다.
- 상태 모델 교체는 하위호환을 만들지 않는다(1단계 사용자는 사실상 개발자 본인뿐). 기존 상태
  파일이 있으면 새 형식으로 **초기화**하고, 그 사실을 로그로 남긴다.
- 도감 그리드(1025칸)는 지연 로드가 실제로 걸렸는지 렌더 측정으로 확인한다.
